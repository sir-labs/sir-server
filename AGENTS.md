# AGENTS.md — sir-server

This repo owns the gateway: nginx config generated by `gateway/watcher`, the sir-auth login
gate, and the routing labels every other service relies on.

## Durable data belongs to sir-dataset

Application data and files live in the central store, `sir-dataset` — never in a service's
own volume, and never in this repo's workspace:

| What | Address on `sir-server_sir-net` |
|---|---|
| API | `sir-dataset-api-1:8000` |
| Postgres | `sir-dataset-db-1:5432` |
| Objects (MinIO) | `sir-dataset-minio-1:9000` |
| Events (RabbitMQ) | `sir-dataset-rabbitmq-1:5672` |

Services address each other **by container name** on `sir-server_sir-net`, never through a
public hostname — a service calling `https://dataset.sir-labs.com` would take a round trip
through cloudflared and the login gate to reach a container next door.

Physical storage lives under `~/.sir-labs` (`$SIR_LABS_DATA`) on the host.

## What the gateway guarantees, and what depends on it

Every route is gated by default: nginx `auth_request` → sir-auth `/session/verify`, then
`X-Auth-User-Id`/`X-Auth-Email`/`X-Auth-Role` are set for the backend and a `Bearer sirpat_`
token is stripped. `sir-mcp` and `sir-dataset` have **no auth code of their own** — they trust
that header and refuse requests from any peer that is not nginx.

So: never add `proxy.auth=false` to `mcp.sir-labs.com`, `dataset.sir-labs.com`,
`ocr.sir-labs.com` or `whisper.sir-labs.com`, and never mark them public in `/admin/routes`.
Doing so does not weaken a login page — it hands anonymous callers the ability to assert any
user id.

When nginx's container IP changes, the services pinning it (`MCP_GATEWAY_IPS`,
`DATASET_GATEWAY_IPS`) must be redeployed, or they will start refusing the gateway.

`proxy.max_body_size` is per route and must be at least as large as the upload limit the
backend enforces, or nginx returns 413 before the app ever sees the request.

sir-auth's own Postgres is deliberately separate from the central store. Leave it alone.
